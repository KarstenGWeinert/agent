# Switch the dev-container's terminal multiplexer from tmux to herdr

The `agent` dev-container replaces tmux with [herdr](https://herdr.dev) (v0.9.1, pinned) as its terminal multiplexer, because herdr reads each pane and marks its coding agent as `working`/`blocked`/`idle`, so a user no longer hunts pane-by-pane for the agent that is waiting on them — the core reason opencode sessions run in a multiplexer at all.

We chose herdr over staying on tmux because tmux has no notion of an agent's semantic state; a user must inspect every pane to find a blocked or idle agent. We chose herdr over another multiplexer (e.g. zellij) because herdr is agent-native: its CLI and socket API are the same surface the agent itself drives, and it detects opencode out of the box. The trade-off is maturity — herdr is newer than tmux — accepted because the container's multiplexer is a workflow aid, not a critical path. The switch is a full replacement, not a coexistence: tmux leaves the `Dockerfile` (apt install, `/etc/tmux.conf`, and the `.bashrc` auto-attach), and herdr is installed from the pinned GitHub release, configured via `~/.config/herdr/config.toml`, and auto-attached on SSH login exactly as tmux was.
