# Deliver R packages as apt binaries via r2u (R 4.6)

The `agent` dev-container stops installing CRAN packages through Posit Package Manager (PPM) binaries plus `pak`, and instead installs them from the r2u apt repository as `r-cran-*` binaries, which requires upgrading the container's R from Ubuntu noble's 4.3 to 4.6.

The trigger was the `highs` package: HiGHS was the one package PPM could not serve as a binary (it compiles a vendored C++ solver from source, one of the slowest steps in the image). No binary of the R `highs` package exists for R 4.3 — PPM ships source only, and r-universe and r2u both build their binaries against R 4.6. So getting a binary `highs` forces R 4.6, and R 4.6 in turn invalidates the PPM setup, because PPM only publishes noble binaries for the distribution's default R 4.3. We therefore adopt r2u wholesale: R base from the marutter `rrutter4.0` PPA and every CRAN package — compiled or pure R — as an `r-cran-*` apt binary, so apt resolves the full dependency closure (including `pak`) as binaries with no source compilation.

We chose r2u over the alternatives: staying on PPM would mean either keeping the R 4.3 source compile of `highs` (defeating the goal) or source-compiling half the package list under R 4.6. r-universe builds its binaries against Ubuntu 26.04 (resolute), not noble. The trade-off is a hard R version bump and a new package-delivery mechanism; accepted because r2u is the only path that makes every compiled package — including `highs` — a real binary on noble.
